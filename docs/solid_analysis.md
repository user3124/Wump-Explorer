# Анализ SOLID

Проведен первичный осмотр кодовой базы проекта. Выявлены ключевые нарушения архитектурных принципов.

## Нарушение SRP (Принцип единственной ответственности)
Класс `CliManager` в файле `CliManager.kt`. Этот класс делает сразу две вещи. Он и парсит входящие аргументы через библиотеку, и сам же содержит функцию `showHelpAndExit`, которая выводит текст справки в консоль через `println`.
* **Как исправить.** По-хорошему, вывод текста надо забрать у парсера и отдать какому-нибудь другому объекту, который умеет просто печатать логи.

## Нарушение OCP (Принцип открытости / закрытости)
Метод `main` в файле `Main.kt`. Проверка действий (`Action.valueOf`) жестко завязана на Enum. Если мы захотим добавить новую команду, например `DELETE`, нам придется лезть в рабочий код `Main.kt` и переписывать там условия. Класс закрыт для расширения.
* **Как исправить.** Вынести обработку действий в отдельные классы команд, чтобы новые действия можно было добавлять без изменения старого кода.
